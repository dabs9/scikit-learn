### F1 — HDBSCAN default `n_jobs=4` diverges from documented default and defeats joblib.parallel_backend
severity: medium
evidence: sklearn/cluster/_hdbscan/hdbscan.py:658 — `__init__` signature has `n_jobs=4,`, while the same file's docstring at lines 486–490 states `n_jobs : int, default=None. Number of jobs to run in parallel to calculate distances. None means 1 unless in a joblib.parallel_backend context.` The value propagates verbatim through `kwargs["n_jobs"] = self.n_jobs` (line 769–775) to `pairwise_distances(..., n_jobs=n_jobs, ...)` (line 245) and `NearestNeighbors(..., n_jobs=n_jobs, ...)` (line 341).
scenario: "user does `with joblib.parallel_backend('loky', n_jobs=1): HDBSCAN().fit(X)` → 4 worker processes still spawn because the concrete `n_jobs=4` is passed through rather than sentinel `None` → resource-oversubscription and behavior contrary to what the docstring promises"
contract: Change the `__init__` default to `n_jobs=None` so both `pairwise_distances` and `NearestNeighbors` see `None` and respect the joblib parallel backend context, matching the documented contract.
instances: single-instance

### F2 — Sparse mutual-reachability leaves raw distance when MR is infinite and `max_distance <= 0`
severity: medium
evidence: sklearn/cluster/_hdbscan/_reachability.pyx:206–212 — `mutual_reachibility_distance = max(core_distances[row_ind], core_distances[col_ind], data[i]); if isfinite(mutual_reachibility_distance): data[i] = mutual_reachibility_distance; elif max_distance > 0: data[i] = max_distance` (no `else`). Combined with lines 195–200, `core_distances[i] = INFINITY` whenever row `i` has `<= further_neighbor_idx` stored entries. With the caller default `max_distance = metric_params.get("max_distance", 0.0)` (hdbscan.py:249), the `elif` is false and `data[i]` is silently kept at its original raw value instead of INFINITY.
scenario: "sparse precomputed distance matrix where some row has fewer than min_samples nonzero entries but is not fully isolated (still reachable via other edges); default max_distance=0.0 → those `data[i]` entries retain the original raw distance instead of INF → `csgraph.connected_components` still reports one component (no ValueError raised in `_brute_mst`) → `csgraph.minimum_spanning_tree` picks these bogus low-weight edges → resulting MST/clustering silently uses wrong reachability weights"
contract: In the `elif` branch write `data[i] = INFINITY` (via `libc.math.INFINITY`) so the sparse matrix consistently reflects the computed mutual-reachability semantics; only override with `max_distance` when the caller explicitly opts in.
instances: single-instance

### F3 — `_weighted_cluster_center` crashes when non-finite samples exist and `store_centers` is set [out-of-theme]
severity: high
evidence: sklearn/cluster/_hdbscan/hdbscan.py:733,840–844,855,907–909,895 — in `fit`, line 733 rebinds `X = X[finite_index]` (reduced-size feature array) inside the `if not all_finite:` branch; lines 840–844 rebind `self.labels_ = new_labels` at full `self._raw_data.shape[0]`; line 855 then calls `self._weighted_cluster_center(X)` with the reduced X. Inside the helper at lines 907–909, `for idx in range(n_clusters): mask = self.labels_ == idx; data = X[mask]` — `mask` has `self._raw_data.shape[0]` entries while `X.shape[0]` is smaller, so `X[mask]` raises `IndexError: boolean index did not match indexed array along dimension 0`. In addition, line 895 `n_clusters = len(set(self.labels_) - {-1, -2})` fails to subtract `-3` (the missing-sample outlier label), inflating `n_clusters` by 1 whenever missing samples exist.
scenario: "`HDBSCAN(store_centers='centroid').fit(X)` with any `np.nan`/`np.inf` in `X` → `all_finite` becomes False → after remap, `self.labels_.shape[0] > X.shape[0]` → `_weighted_cluster_center` raises IndexError at the first cluster iteration; user cannot get centroids/medoids for non-finite inputs at all"
contract: Compute the mask against labels aligned to the reduced `X` (e.g., `mask = self.labels_[finite_index] == idx`, or pass `self._raw_data` to `_weighted_cluster_center` and mask against that), and drop `-3` in addition to `{-1, -2}` when counting non-noise clusters.
